# 模板目录与排版

版式页提供 21 款模板，可按简洁、正式、双栏、创意、侧重点分类，或搜索名称、用途和模板 ID。切换模板保留正文、组件 ID 和批注；校园、能力、项目模板只把相应模块优先显示，不改存储顺序。

## Sub-features

- `catalog_filters` 检查完整目录、分类按钮状态、用途与 ID 搜索、无结果提示。
- `template_<id>` 逐款点击并检查选中状态、存储值、正文不变、屏幕与打印页面的全部组件 ID 无丢失和重复。默认示例必须一页 A4、无横向溢出，PDF 包含全部中文和末尾内容。
- `complex_<id>` 在左题、右栏、双列、横幅中放入长中文、连续英文、长网址、合成照片、空列表模块、空段落模块和结尾标记。检查节点与照片保留、横向边界及 PDF 全文。
- `overrides_<id>` 在书卷、左题、横幅、右栏中选择标题样式及 90% 或 110% 字号，核对实际样式、存储和 PDF。
- `template_history_restore` 检查代表模板刷新、撤销重做、备份下载及恢复，正文始终不变。

## How to get to it (user POV)

- 左栏“版式”页，使用“搜索模板”或“模板分类”，再点模板缩略图。
- 同页调整“标题样式”和“字号”。
- 使用工具栏撤销重做；到“版本”页下载或恢复备份。

## Driving it with core-flow

先由当前源码构建，再运行 `node e2e/templates.mjs`。可追加案例 ID 单独调试，例如 `node e2e/templates.mjs template_ledger complex_sidebar-right`。`REDLINE_HTML` 指定构建，`TEMPLATES_OUT` 指定证据目录，默认 `e2e/out/templates`。

每条案例使用全新临时 Chrome 上下文，不读取真实 Key，并阻止所有网络请求。报告含 HTML SHA-256、浏览器版本和逐案例状态；每款模板保留截图、PDF、普通文本提取及原始文本提取。完整发布必须跑全部案例，不能用单条调试报告代替全量验收。

## Gotchas

- 一页承诺只针对默认示例和当前测试环境。真实内容、照片、字号和本机字体会改变页数；复杂内容案例检查完整性，不承诺任意长内容都是一页。
- PDF 提取器会自行判断阅读顺序，可能交错处理标题或双栏，或去掉行末网址连字符。脚本用 `pdftotext -raw` 核对完整文本流，同时保留普通提取结果供检查；不据此保证招聘系统识别效果。
- 仿宋的描边加粗可能在原始 PDF 文本流中出现重复字形；不能把它当成 DOM 组件重复。组件重复由 `data-node` 检查独立判定。
- 照片是测试生成的合成图，不使用用户文件。长网址使用不会访问的 `example.invalid` 域名。
- 系统打印对话框、真实招聘网站和其他浏览器不在这组验收范围内。
